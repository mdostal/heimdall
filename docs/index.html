What it does

One service. Four jobs.

Heimdall replaces ad-hoc health checks scattered across every orchestrator with a single contract your whole fleet can depend on.

👁️

4-State Health Sensing

Layers passive observation, provider status-page polling, and sparse active probes into a single authoritative lane state — up, down, out_of_credit, or degraded — with a corroboration guard against flapping.

GET /lanes
🔀

Pluggable Lane Routing

Routes tasks to the best healthy lane via a swappable strategy. The default scored strategy weighs health state, priority, and provider cost; supports A/B testing with outcome feedback so routing improves over time.

GET /available-route
⚙️

Multica Actuation

Closes the loop: when a lane goes down, Heimdall toggles max_concurrent_tasks on the mapped Multica agents to zero so work stops flowing there — and restores it automatically when health recovers.

MulticaControlAdapter
📋

Live Model Catalog

Maintains a per-installation model catalog sourced from each provider so agents stop calling deprecated models. Models are available via the MCP surface alongside lane health, making the catalog queryable by any MCP-capable tool.

MCP · HTTP

Quick Start

Up in two minutes

Heimdall runs as a local service. Requires Node.js ≥ 22.13.0 (uses the built-in node:sqlite module).

curl -fsSL https://mdostal.github.io/heimdall/install.sh | bash

Or clone and run directly:

# Clone and install
git clone https://github.com/mdostal/heimdall.git
cd heimdall
npm install

# Declare your lanes (provider × account × runtime triples)
cp .env.example .env
# Edit .env — set HEIMDALL_LANE_1_ID, _PROVIDER, _CREDENTIAL_REF …

# Start the service
npm run dev         # → http://localhost:4870

Check GET /lanes to see your declared lanes and their health. Full configuration reference: ops/configuration · .env.example

Architecture at a glance

Where Heimdall fits

A single daemon between your orchestrators and every LLM provider — not a library, not a sidecar.

Heimdall is one god in Pantheon, the open-source agent ecosystem hosted at mdostal/pantheon-v2. It owns the sensing-and-actuation contract for every LLM/runtime lane — a provider × account × runtime triple — so that no other service needs to re-implement health checking.

Auriga (the router/orchestrator) calls GET /available-route when dispatching a task; it gets back the best healthy lane and never needs to know what state each provider is in. Vesta owns lane and agent config. Argus receives Heimdall's OTEL telemetry.

Internally, schedulers tick each lane on a coarse Multica autopilot cron plus a fine in-process loop for suspect lanes. The lane pipeline gathers layered signals, the status-model resolves them into a 4-state verdict, and the ControlAdapter reconciles Multica agent concurrency accordingly.

The signal loop

1
Scheduler ticks — Multica autopilot (coarse cron) or in-process loop (~5s, suspect lanes)
2
Lane pipeline gathers signals — passive observation → provider status page → sparse active probe
3
Status-model resolves — corroboration guard prevents flapping; outputs one of four states
4
State stored to SQLite — queryable via HTTP, CLI, and MCP surfaces
5
ControlAdapter actuates — sets max_concurrent_tasks on mapped Multica agents to open or close the lane
